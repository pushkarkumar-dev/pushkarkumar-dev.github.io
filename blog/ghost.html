Why this matters

Everyone judges a model by the wrong number

When a new model drops, the timeline argues about one thing: is it smarter? But if you let AI touch real code, the score that decides your weekend is different.

It's not "can it solve a hard problem." It's "how often does it hand you code that looks correct, passes a quick glance, and quietly breaks later." That's the ghost bug. Opus 4.8 is Anthropic's attempt to shrink exactly that gap, and it's why a tiny benchmark bump is hiding a real upgrade.

How to actually catch AI's mistakes

The mistake most people make: they read AI code the way they read their own, top to bottom, nodding. AI bugs don't live where you look. Here's the order I actually check, fastest payoff first.

  • Boundaries before logic. Empty input, one item, the last item, off-by-one. AI loves a clean middle and a broken edge.
  • Silent failure paths. Search for swallowed errors and bare catches. AI hides problems to make output "work."
  • Assumptions about types & order. Sorting, equality, truthiness. The classic below bites everyone.
  • The thing it didn't ask about. Concurrency, auth, rate limits, money. If you didn't specify it, assume it's wrong.
  • Make it grade itself. Paste the code back and ask: "List the 3 most likely bugs and the inputs that trigger them." 4.8 is noticeably better at this than older models.

A real ghost bug an AI will hand you with a straight face:

// "Sort these IDs ascending" — looks done, passes the demo
const ids = [2, 10, 1, 30];
ids.sort();
// → [1, 10, 2, 30]  // WRONG. JS sorts as strings by default.

// The fix it should have written:
ids.sort((a, b) => a - b);
// → [1, 2, 10, 30]  // correct

No test catches this if your test data happens to be single-digit. That's a ghost bug: green checkmark, wrong answer in production.

The cost math

Same sticker price, cheaper in practice

The base rate didn't move: $5 per 1M input, $25 per 1M output, held since Opus 4.5. Two things quietly changed the real bill:

  • Fast Mode is ~3x cheaper than before. Runs at ~2.5x standard speed for $10 / $50 per 1M. Frontier reasoning is now usable for interactive, latency-sensitive work.
  • Prompt caching still ~90% off reads (~$0.50/M). The tokenizer didn't change from 4.7, so existing cache entries should carry over. Validate on your own prompts.

Reality check for your wallet: Opus is still the expensive tier. For most workloads, Sonnet 4.6 or Haiku 4.5 is the right default. Reach for Opus 4.8 when autonomous reasoning or code quality is the whole point.

The shiny new toy

Hundreds of helper agents at once

Opus 4.8 shipped alongside Dynamic Workflows in Claude Code: it can plan a job and fan it out to hundreds of parallel subagents (little helpers that each take one slice of the work). Built for codebase-scale jobs, big migrations, sweeping refactors.

The money move: run the orchestrator on Opus 4.8 and the subagents on a cheaper model (Sonnet tier). Run everything on Opus and your bill jumps 3–5x. The economics make sense when the workflow replaces multiple engineer-days, not for a casual refactor.

Dynamic Workflows is a research-preview feature on paid Claude Code tiers. Available surfaces for the model: Claude API, Amazon Bedrock, Google Vertex AI, Microsoft Foundry, and GitHub Copilot (generally available day one).
